# Форматы

Imager поддерживает широкий набор растровых форматов через libvips, а также извлечение кадров из видео. В этом документе перечислены реальные возможности каждого формата: чтение, запись, анимация, альфа-канал.

Связанные документы: [ARCHITECTURE.md](ARCHITECTURE.md), [PROCESSING.md](PROCESSING.md), [API.md](API.md), [AI.md](AI.md).

## Растровые форматы

| Формат | Чтение | Запись | Анимация | Альфа | Примечания |
|--------|:------:|:------:|:--------:|:-----:|------------|
| JPEG | ✅ | ✅ | — | ❌ | Shrink-on-load (степени 2), без альфа-канала |
| PNG | ✅ | ✅ | — | ✅ | Palette-режим при низком качестве |
| WebP | ✅ | ✅ | ✅ (lossy/lossless) | ✅ | Scale-on-load |
| GIF | ✅ | ✅ | ✅ | ✅ | Палитровый, анимация |
| AVIF | ✅ | ✅ | ✅ (libheif ≥ 1.23) | ✅ | Нативный sequence-энкодер libheif |
| HEIF / HEIC | ✅ | ✅ | ❌ | ✅ | Анимация НЕ поддерживается (см. ниже) |
| JXL (JPEG XL) | ✅ | ✅ | ✅ | ✅ | |
| APNG | ✅ | ✅ (только при libspng) | ✅ (вход) | ✅ | Выходная запись требует libspng |
| TIFF | ✅ | ✅ | — | ✅ | |
| BMP | ✅ | ✅ | — | ✅ | |
| JP2K (JPEG 2000) | ✅ | ✅ | — | ✅ | |
| PSD | ✅ | — | — | ✅ | Только чтение |
| RAW (CR2/NEF и др.) | ✅ | — | — | — | Только чтение |
| SVG | ✅ | — | — | ✅ | Passthrough (без растеризации) |
| PDF | ✅ | — | — | — | Только чтение (первая страница) |

### Важные ограничения

#### APNG — запись только при libspng

APNG поддерживается как **входной** формат (чтение анимированного PNG). **Запись** в APNG доступна только при сборке с `libspng`; без него выходной APNG недоступен (маршрутизация вернёт ошибку недоступности движка).

#### Анимированный HEIF/HEIC — НЕ поддерживается

Запись анимированного HEIF/HEIC **не поддерживается**: из-за бага HEVC-энкодера в libheif 1.23 при попытке сохранить последовательность кадров возвращается только статичный первый кадр. Поэтому анимация в HEIF/HEIC не заявлена.

#### Анимированный AVIF — поддерживается

В отличие от HEIF/HEIC, анимированный AVIF **поддерживается** через нативный sequence-энкодер libheif (требуется libheif ≥ 1.23). Это реализовано в vendored-форке govips (`govips/vips/heif_sequence.go`).

#### Анимированные GIF и WebP — поддерживаются

Анимация GIF и WebP (lossy/lossless) поддерживается полностью: чтение, обработка по кадрам, запись.

## Видео

Imager **не** транскодирует видео. Для видео-исходников выполняется **извлечение кадра** (ffmpeg/ffprobe) с последующей обработкой кадра как изображения. Поддерживаемые видео-контейнеры (15):

`mp4`, `webm`, `mov`, `mkv`, `avi`, `m4v`, `mpg`, `mpeg`, `wmv`, `flv`, `3gp`, `ogv`, `ts`, `mts`, `m2ts`

Параметры извлечения кадра (секция `video` конфигурации):

| Параметр | По умолчанию (код) | Shipped-конфиг | Описание |
|----------|:------------------:|:--------------:|----------|
| `frame-percent` | 50 | 2 | Процент длительности, на котором берётся кадр |
| `frame-step` | 1 | 25 | Шаг кадров при поиске |
| `attempts` | 3 | 3 | Число попыток извлечения |
| `min-contrast` | 0.05 | 0.05 | Минимальная контрастность кадра |
| `extract-timeout` | 60 с | 60 с | Таймаут извлечения |

Извлечённый кадр кэшируется как `x.jpg` (sidecar-ключ `video_frame_key`).

## Кодирование

### Качество

- Дефолтное качество: 85 (shipped-конфиг).
- Качество задаётся в пресете/custom (`quality`, 0–100; `0` = `encoders.default-quality`). Параметра `q` в URL нет.

### Автоматическое маппинг-сопоставление параметров кодеков

Параметры кодеков автоматически сопоставляются с качеством (anchor mapping, `domain/encoding/mapping.go`):

| Кодек | Параметр | Маппинг |
|-------|----------|---------|
| WebP | `reduction-effort` | q75 → 4 |
| AVIF | `speed` | q80 → 6 (инверсный) |
| JXL | `effort` | q75 → 7 |
| GIF | `effort` | q75 → 7 |
| PNG | `compression-level` | q85 → 6 |
| PNG | `palette` | q<90 → ON |

Приоритет: переопределение в пресете → секция `encoders` YAML → автоматический маппинг → дефолт реестра.

### Цветовое управление (ICC)

| Режим | Описание |
|-------|----------|
| `strip` (по умолчанию) | Профиль удаляется, метаданные не сохраняются |
| `transform` | Трансформация в sRGB через PCS |
| `keep` | Профиль сохраняется |

### Метаданные

- DPI нормализуется к 72.
- Метаданные (EXIF/GPS/XMP/IPTC) удаляются при обработке.
- Passthrough fast-path: если запрос не требует операций, исходник может быть отдан без перекодирования.

## Shrink-on-load

Для ускорения обработки больших изображений применяется уменьшение при загрузке:

- JPEG: power-of-2 shrink.
- WebP / HEIF / AVIF / GIF: scale-on-load.

Shrink-on-load **не** применяется при: `trim`, `smart-crop`, `face-crop`, `object-crop`, ручной ориентации, `size=x` (только ширина), анимированном GIF.

## Ограничения

- Максимальный размер стороны: 1 048 576 px (`MaxDimension`).
- Максимальный размер URL: 1024 байта.
- Максимальная длина пути: 512 байт.
- Максимальная длина имени источника: 128 байт.
- Максимальная длина формата: 16 байт.
- Максимальная длина имени пресета: 64 байта.
